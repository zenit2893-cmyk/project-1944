# Пересборка порта из вашего образа диска

Кнопка «Рекомпилировать игру из вашего образа диска» в лаунчере делает то же, что делает разработчик: распаковывает образ, переводит код Xbox 360 в C++ и компилирует его в нативное приложение. Пакет теперь умеет доставать всё, чего ему не хватает, сам.

## Что уже лежит в пакете

Инструменты сборки входят в архив, в каталоге `tools/toolchain-bundle`, и ставятся оттуда без сети.

| Компонент | Размер в архиве | Лицензия |
|---|---|---|
| Clang/LLVM 22.1.8 | 286 МБ | Apache-2.0 WITH LLVM-exception |
| CMake 4.4.3 | 21 МБ | BSD-3-Clause |
| Ninja 1.13.2 | 1 МБ | Apache-2.0 |
| xdvdfs 0.8.3 (распаковщик образа) | 3 МБ | MIT |
| CPython 3.12 (переносимый, с PortableMSVC) | 67 МБ | PSF-2.0 |
| Модули Python для анализа образа | 19 МБ | BSD/Apache |
| uv (запасной путь) | 41 МБ | MIT / Apache-2.0 |

LLVM поставляет один и тот же двоичный файл под несколькими именами — драйвер узнаёт себя по `argv[0]`. В архиве он лежит один раз, а остальные имена воссоздаются жёсткими ссылками при установке. Поэтому после установки `bin` выглядит на 783 МБ, а занимает на диске 246 МБ.

## Что пакет не может нести и добывает сам

| Компонент | Почему | Как появляется |
|---|---|---|
| MSVC 14.44 и Windows SDK 10.0.26100 | Лицензия Microsoft запрещает перераспространение | Сначала ищется уже установленная Visual Studio через `vswhere`; если её нет — PortableMSVC качает с серверов Microsoft, около 280 МБ, без вопросов |
| Образ игры и её файлы | Игровые данные не распространяются | Ваша копия |
| Мост Xenon, C++ кода игры | Код производный от игры | Генерируются из **вашего** образа готовыми `XenonRecomp` и `rexglue.exe` |

MSVC нужен только для полной компиляции (см. ниже) — это единственная оставшаяся загрузка. Почему её нельзя убрать — в [legal.md](legal.md). `rexglue.exe`, XenonAnalyse и XenonRecomp лежат в пакете готовыми под GPL-2.0-or-later вместе с полными исходниками (`sdk-source/`, `tools/XenonRecomp/`).

Посмотреть, что уже есть и что будет доставаться, можно не открывая окно:

```powershell
powershell -ExecutionPolicy Bypass -File launcher\Cod3Launcher.ps1 -CheckRebuild
```

## Что нужно от вас

1. Ваша копия Call of Duty 3 для Xbox 360: каталог `game\cod3` с `default.xex` рядом с пакетом, либо образ диска, который лаунчер распакует сам.
2. PowerShell 7 — скрипты сборки объявляют его требованием.
3. Место на диске: около 7 ГБ на инструменты плюс десятки гигабайт на сгенерированный C++ и объектные файлы.
4. Интернет — только для полной компиляции и только если на машине нет Visual Studio: тогда скачается MSVC с Windows SDK, около 280 МБ. Всё остальное берётся из архива.

## Быстрая рекомпиляция (около минуты)

Рекомпиляция — это перевод кода игры (`default.xex` и 15 модулей уровней) в C++. Он делается из вашей копии готовыми `rexglue.exe` и XenonRecomp и компилятора не требует: на 8-ядерном ПК от чистой распаковки до конца — 76 с, из них сама рекомпиляция (мосты, кодогенерация, сверка) — 53 с.

Дальше `scripts/complete-recompile.ps1` сравнивает результат с `analysis/recompile-reference.json` — SHA-256 кода, из которого собрана готовая сборка пакета. Кодогенератор раскладывает функции по файлам по сохранённой раскладке (`cod3-pc/generated/*/codegen.partition.json` идёт в пакете), поэтому для поддерживаемой ревизии вывод совпадает байт в байт; тогда компиляция дала бы ту же самую сборку, и она берётся готовой (квитанция — `analysis/recompile-receipt.json`). Если отличается хоть один файл или изменены исходники порта, а также по кнопке «Пересобрать игру» (`-RebuildNow -FullCompile`), игра компилируется полностью: компилятор ставится тем же шагом, графический плагин берётся готовый из пакета.

## Как идёт пересборка

Лаунчер выполняет шаги по порядку и показывает журнал. Пропускается всё, что уже сделано.

1. **Распаковка образа** — только если `game\cod3\default.xex` ещё нет. `scripts/extract-cod3.ps1` сверяет SHA-256 образа с поддерживаемой ревизией диска и извлекает файлы через `xdvdfs`. Если вместо образа выбран `default.xex` уже распакованной игры или пакет Games on Demand (`415607E1\00007000\<заголовок>` + `<заголовок>.data\Data0000…`), этот шаг заменяет `scripts/copy-cod3-game.ps1 -Source <default.xex, папка или GOD>`. GOD читается напрямую, без промежуточного образа: части Data — это блоки по 4 КБ с хеш-таблицами (203 подчасти по 204 блока на файл), внутри — файловая система диска XDVDFS. SHA-256 `default.xex` сверяется с `analysis/disc-source-lock.json` до записи чего-либо; код (`*.xex`, модули уровней `*.dll`) должен совпасть с `analysis/disc-file-manifest.csv` побайтно, все файлы диска должны быть на месте, а данные (`.wbk`, `.cod`, `.wma`) могут отличаться — так выглядят издания с другой озвучкой; такие файлы ставятся как есть и перечисляются в журнале. Установка идёт через `game\cod3.partial` и продолжается после обрыва; `xdvdfs` в этом случае не нужен.
2. **Подготовка инструментов** — `tools/toolchain-provision/Install-Toolchain.ps1 -Component tools` раскладывает из архива переносимый CPython (`tools/toolchain/bootstrap-python`, собирается `New-BundledPython.ps1`; не venv — venv хранит абсолютный путь к исходному Python и на чужой машине не запускается) и модули анализа. Компиляторы (`-Component all`: CMake, Ninja, Clang, MSVC) ставятся здесь только для полной компиляции.
3. **Мост Xenon** — `tools/xenon-bridge-build/Build-XenonBridge.ps1`. Готовым XenonRecomp разбирает ваш `default.xex` и извлекает два проверенных переходника, сверяя и опкоды, и текст сгенерированного тела. Чужая ревизия игры на этом шаге остановится, а не подключит непроверенный код.
4. **Мост корутин** — `integration/coroutines/Prepare-FromGame.ps1`.
5. **Кодогенерация** — `cod3-pc/cmake/Invoke-Codegen.ps1`: ReXGlue отдельным процессом на каждый из 16 образов.
6. **Проверка моста корутин** по сгенерированному коду.
7. **Сверка и компиляция** — `scripts/complete-recompile.ps1` (см. выше); при полной компиляции — `scripts/build-cod3.ps1`, который сверяет ревизию XEX, собирает приложение и 15 библиотек уровней и записывает квитанцию сборки с хешами.

Если `rexglue.exe` или XenonRecomp в пакете нет, они собираются из исходников (`tools/rexglue-cli/Build-RexGlueCli.ps1`, `Build-XenonBridge.ps1`), и тогда компилятор ставится на шаге 2.

То же самое без окна:

```powershell
powershell -ExecutionPolicy Bypass -File launcher\Cod3Launcher.ps1 -RebuildNow -Iso "D:\путь\к\образу.iso"
```

## Антивирус и Smart App Control

Полный разбор — в [antivirus.md](antivirus.md): что именно срабатывает, почему и три способа это убрать. Коротко: подпись сборки (`tools/signing/Set-Cod3Signature.ps1`) устраняет причину, исключение Defender (`tools/signing/Set-DefenderExclusions.ps1`, запускаете вы сами из-под администратора) обходит её и заодно заметно ускоряет сборку, а Smart App Control не принимает ни того, ни другого.

## Smart App Control может остановить сборку

Если в Windows включён Smart App Control, он отказывается запускать только что собранные неподписанные программы. Компиляция при этом проходит, а вот запуск — нет, и шаг падает с сообщением «Политика управления приложениями заблокировала этот файл». Лаунчер предупреждает об этом заранее.

Блокировка выборочная: один свежий инструмент может запускаться, а соседний — нет, и иногда она снимается сама через некоторое время после первой попытки. Отключается в «Безопасность Windows» → «Управление приложениями и браузером» → «Smart App Control». Отключение необратимо, поэтому решение принимаете вы.

## Если сборка остановилась

Журналы шагов лежат в `logs\` рядом с пакетом: `prepare-*.log` для подготовки, `cod3-pc-build-*.log` для компиляции. Частые причины:

- образ диска другой ревизии: скрипт распаковки сверяет хеш и отказывается работать с неизвестным образом;
- не найден `pwsh.exe`: поставьте PowerShell 7;
- не хватает места: полное дерево сгенерированного C++ и объектных файлов занимает десятки гигабайт;
- нет интернета: шаги установки инструментов скачивают их с сайтов правообладателей.
