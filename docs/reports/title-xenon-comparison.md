# XenonRecomp: проверенные адреса и реальный результат

На исходном `default.xex` выполнена независимая перекомпиляция XenonRecomp `ddd128bcca99fe8bfbb99bea583c972351fa6ace`. Инструмент создал 82 файла общим размером 96 974 787 байт. Генерация содержит диагностические ошибки и не является готовой заменой всей программы. Два простых branch thunks выделены для ограниченного подключения к ReXGlue отдельным integration-модулем.

## Адреса helper-функций

Все восемь функций найдены однозначно. Проверены полные последовательности сохранения/восстановления регистров, смещения стека, номера регистров и завершающий `blr`, а не только первые байты.

| Ключ `[main]` | Адрес | Проверено байт |
|---|---|---:|
| `restgprlr_14_address` | `0x8234F2B0` | 84 |
| `savegprlr_14_address` | `0x8234F260` | 80 |
| `restfpr_14_address` | `0x8234FA1C` | 76 |
| `savefpr_14_address` | `0x8234F9D0` | 76 |
| `restvmx_14_address` | `0x8234FD08` | 148 |
| `savevmx_14_address` | `0x8234FA70` | 148 |
| `restvmx_64_address` | `0x8234FD9C` | 516 |
| `savevmx_64_address` | `0x8234FB04` | 516 |

Проверка воспроизводится `scripts/analyze-title-xenon.py`. Машиночитаемые байтовые последовательности, SHA256 каждого helper, число совпадений и примеры прямых переходов сохранены в `analysis/title-xenon-helpers.json`. Готовый фрагмент `[main]` — `analysis/title-xenon-helpers.toml`. Все значения относятся только к XEX SHA256 `2944EEC7D1231AD6798B5F9F8ADF8855F5E489296B22EAB45B27A577CEE23692`.

Схема взята из [официального README XenonRecomp](https://github.com/hedge-dev/XenonRecomp/blob/ddd128bcca99fe8bfbb99bea583c972351fa6ace/README.md). Разбиение номера VMX128-регистра проверено по `thirdparty/disasm/ppc-dis.c` в том же checkout. Capstone не декодирует использованные расширенные VMX128-инструкции, поэтому для них применена проверка исходных полей инструкции, а не несуществующий вывод дизассемблера.

Адреса `setjmp`/`longjmp` не подставлялись: их семантическая идентификация не выполнена. Наличие импорта `RtlUnwind` само по себе не даёт достаточного основания угадать эти функции.

## Выполненные инструменты

Root-процесс запустил XenonAnalyse и создал `analysis/xenon-switch-tables.toml`: 323 таблицы по 323 уникальным адресам, 5 095 элементов labels. Затем выполнен:

```powershell
tools/XenonRecomp/out/build/windows-release/XenonRecomp/XenonRecomp.exe `
  analysis/title-xenon-config.toml `
  tools/XenonRecomp/XenonUtils/ppc_context.h
```

Минимальный конфиг `analysis/title-xenon-config.toml` ссылается на пользовательский XEX, точные helpers и результат XenonAnalyse. Оптимизации выключены. Внесены только две подтверждённые границы коротких thunks и пропуск реально встречающегося нулевого alignment-слова. Ни XEX, ни конфиг основного ReXGlue-проекта не менялись.

Результат записан в `analysis/title-xenon-generated`, лог — `analysis/title-xenon-recompile.log`, сводка — `analysis/title-xenon-receipt.json`.

| Диагностика | Количество |
|---|---:|
| Exit code | 0 |
| Неподдержанные инструкции | 3 233 появления, 34 мнемоники |
| Ошибки выхода switch label за границы функции | 1 360 появлений, 60 мест |
| Сообщения об отсутствующей записи switch table | 0 |

Среди неподдержанных инструкций встречаются `vslh`, `vsrah`, `vsubshs`, `vspltish`, `vandc`, `vsel128`, `mulhd`, `mulhdu` и другие. Сам по себе exit code 0 у этой версии инструмента не означает, что сгенерированная программа полна и корректна. Полный список частот сохранён в JSON-сводке.

## Подтверждённые короткие thunks

| Guest address | Проверенные исходные слова | Поведение |
|---|---|---|
| `0x822D0498` | `4BFFFC80` | Tail branch на `0x822D0118` |
| `0x822D2140` | `38630004 4BFF98E4` | `r3 += 4`, tail branch на `0x822CBA28` |

XenonRecomp действительно создал их в `analysis/title-xenon-generated/ppc_recomp.32.cpp`, функции `__imp__sub_822D0498` и `__imp__sub_822D2140`. Тела начинаются на строках 11856 и 16094 текущего артефакта; эти номера применимы только к данной генерации. Полные helpers и эти исходные слова также совпали с независимой загрузкой ReXGlue.

Артефакты переданы владельцу `integration/xenon` для подключения только этих двух функций и проверки совместимости `PPCContext`. Получившаяся связка не устанавливает корректность остального XenonRecomp-вывода. Самостоятельный анализ здесь не запускал игру и не доказывает 120 FPS, синхронизацию аудио либо сохранность физики.
